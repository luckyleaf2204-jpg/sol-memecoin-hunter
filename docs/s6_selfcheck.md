## What the self-check found and fixed (it was not all already true)

| Item | Finding during the self-check | Fix |
|---|---|---|
| G1 (b) | A non-HARD exit postponed after 60 s was dropped even when the price had fallen through the stop meanwhile (only the next tick's stop signal would catch it, and a HARD replacing a waiting exit restarted the 60 s window). | `bot._execute_sells`: after the window, a waiting exit whose latest mark is <= the stop becomes a full HARD exit (emergency haircut if still no quote). A HARD signal replacing a waiting exit keeps its `first` retry time. |
| G1 (c) | `run()` awaited the SELL round before the next tick, and SELLs were quoted one after another with up to 3 attempts / 8 s each: N failing quotes delayed every other stop loss by up to N x 8 s. | Execution (SELL then BUY) runs as its own task beside the tick (one round at a time); SELL quotes are concurrent, short (2 attempts / 4 s) and filled as each lands; the bot-level backoff does the retrying. |
| G1 (d) | Not a bug before (sequential), but the concurrent version needed guards. | A second overlapping SELL round returns at once; a fill is skipped if the position, its size or the intent changed while quoting. |
| G1 (e) | Intents are in memory only. | Verified: every exit is re-derived from position + current price on the first tick after a restart (test). |
| G1 (f) | SELL priority existed only as "truth / probe wait while a SELL is pending"; BUY quotes and the 50/min Jupiter limit were not shared. | `trading/quote_budget.py`: one 50/min budget, 10 reserved for SELL; buy / truth / probe never while a SELL waits; a refused SELL / BUY is a transient RATE_LIMITED (retried), never a haircut. |
| G3 | A token blocked first and entered later is in both groups. | Kept in both (dropping it would use later information); counted as `blocked_then_entered`. |
| G5 | — | Added: halted = no bot loop, no scanner, no file, no snapshot (test). |

## Open risks (honest)

1. **The sample is still NOT durable**: no `SNAPSHOT_URL` / `SNAPSHOT_DIR` on Render yet. Until set, every restart
   loses the paper book. Lease and hand-over only work with a store.
2. **The lease is best effort** (no compare-and-swap in a file / HTTP object store). It covers the deploy overlap;
   two instances acquiring within the 2 s settle window are resolved by "last writer wins, the other backs off".
3. **A crash (no SIGTERM)** keeps the lease up to 180 s and loses data since the last hourly snapshot (a GAP).
4. **Price history across a restart** is only reloaded when <= 120 s old; after the hand-over it usually is, after a
   crash it is not (300 s warm-up).
5. **Backtest is an approximation** (model fills, no Jupiter quotes) — not evidence of profit.
6. **No conclusion on profitability is possible yet**: n is 0 for the s7 epoch; the report says
   "Chưa đủ dữ liệu để kết luận có lãi" until n >= 200 and every CI is on one side of 0.
7. `docs/review_bundle.md` in the repo is the offline bundle (no paper data locally); the owner refreshes it from the
   server with `REVIEW_ACCESS_CODE=... python tools/export_review_bundle.py --url https://sol-memecoin-hunter.onrender.com`.
8. `tests/test_stress.py::test_full_evaluation_of_400_tokens_fits_the_budget` is timing-based and flaky on a busy
   machine (passes when rerun alone) — pre-existing.
